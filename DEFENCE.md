# Подготовка к защите

## Объяснение проекта

«Я сделал одностраничную библиотеку. App хранит список книг и фильтры. Каждая BookCard хранит собственное количество прочитанных страниц и заметку. Через props родитель передаёт книгу и обработчики изменения статуса, удаления и сброса».

## 1. Что такое рендер и повторный рендер?

Рендер — вызов функции компонента, которая описывает интерфейс JSX. Обновление состояния через setter может запланировать повторный рендер. Это не означает, что весь DOM будет пересоздан: React сравнит результат с предыдущим и внесёт необходимые изменения.

Нажатие «+10 стр.» обновляет `pagesRead` в одной BookCard. App и другие карточки от этого не должны повторно рендериться. Изменение фильтра обновляет App и вызывает рендер его дочерних карточек: React.memo здесь не используется.

Откройте DevTools → Console. Есть сообщения `[render] App`, `[render] BookCard`, `[reset key]`. Раскройте объект в сообщении для id, edition и состояния. Рендер-логи показывают вызов функции, а не гарантированный commit в DOM. В development при StrictMode возможны дополнительные вызовы; в этой реализации StrictMode не включён, чтобы демонстрация была проще.

## 2. Что такое reconciliation?

Это сопоставление React предыдущего и нового дерева элементов. React учитывает тип элемента, его положение и ключ среди соседей. Он определяет, какую существующую компонентную инстанцию можно использовать, что переместить, что обновить и что размонтировать.

После обратного порядка книги переставляются. Стабильный `id:edition` позволяет сопоставить каждую карточку с той же книгой и сохранить её состояние.

## 3. Что такое идентичность компонента?

Это то, считает ли React элемент продолжением прежней компонентной инстанции. Одно и то же имя JSX само по себе недостаточно: важны тип, положение в дереве и key. Изменение key говорит React, что это другая инстанция.

Компоненты определены вне App. Определять BookCard внутри App было бы ошибкой: при рендере создавалась бы новая функция-типа компонента, что могло бы сбрасывать состояние.

## 4. Почему нельзя использовать индекс как key?

После перестановки индекс описывает позицию, а не книгу. Состояние первой карточки могло бы оказаться у другой книги. Поэтому id создаётся один раз при добавлении через crypto.randomUUID(), а затем хранится в объекте. Нельзя генерировать новый случайный key при каждом рендере.

`number={index + 1}` — только отображаемый номер строки, он не влияет на идентичность. key не передаётся в props автоматически: данные книги передаются отдельно.

## 5. Как сохраняется состояние при фильтрации?

Все книги продолжают рендериться через `.map()`. Неподходящая карточка получает `hidden`, поэтому исчезает визуально и из доступного интерфейса, но остаётся смонтированной. Когда фильтр убирается, та же инстанция показывает сохранённые страницы и заметку.

Важно: стабильный key не является внешним хранилищем состояния. Если убрать карточку из React-дерева, локальный useState уничтожится. Для небольшого учебного списка скрытие подходит; для огромного списка нужна другая архитектура хранения.

## 6. Как работает намеренный сброс?

В App находится `edition` каждой книги. Ключ: `${book.id}:${book.edition}`. При сбросе edition увеличивается только у выбранной книги. Например, `prince:0` становится `prince:1`.

React размонтирует прежнюю BookCard и создаёт новую. Её `useState(0)` и `useState('')` снова дают начальные значения. Родительские данные книги и состояние других карточек не меняются.

## 7. Почему массив копируется?

`reverse()` меняет исходный массив. Используется `[...previous].reverse()`, чтобы сохранить иммутабельность. Для изменения статуса применяется `.map()` с новым объектом нужной книги, для удаления — `.filter()`.

Функциональный setter получает актуальное предыдущее состояние. Например, `setPagesRead(previous => Math.min(previous + 10, book.pages))` корректно опирается на предыдущий счётчик.

## Демонстрация на 3–5 минут

1. Откройте сайт и Console, очистите логи.
2. У «Маленького принца» дважды нажмите «+10 стр.» и напишите заметку. Покажите рендер только этой карточки.
3. У «Хоббита» нажмите «+10 стр.». Получатся разные состояния: 20 и 10.
4. Нажмите «Обратный порядок». Состояния остались у своих книг.
5. Выберите «В планах», затем «Все книги». Принц снова появится с 20 страницами и заметкой.
6. Найдите книгу через поиск; очистите поиск.
7. Смените статус книги и покажите соответствующий фильтр.
8. Сбросьте прогресс Принца: у него 0 и пустая заметка; у Хоббита по-прежнему 10. Покажите код key и edition.
9. Добавьте книгу, затем удалите её.
10. Покажите условное отображение формы и пустого результата.

Не нужно заучивать текст дословно: разберитесь с потоком данных и проделайте этот сценарий самостоятельно.
